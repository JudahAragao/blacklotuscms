# Theme Engine Flows

## Render Public Page

1. **Public route detects context** (single, archive, search, 404)
   - State: Context determined

2. **ThemeRenderer fetches active theme**
   - `ThemeService.getActiveTheme()`
   - State: Theme name obtained

3. **Theme name sanitization**
   - `sanitizePath(rawThemeName)`
   - State: Safe theme name

4. **Registry validation**
   - Checks if theme exists in `themeRegistry` (generated by `themes:generate`)
   - If not: fallback to `default`
   - State: Theme validated

5. **Data masking**
   - `maskSensitiveData(data)`
   - State: Safe data

6. **Layout resolution**
   - `themeRegistry[themeName][layoutKey]` → React Server component
   - Fallback: `themeRegistry[themeName].post` or `themeRegistry.default.post`
   - State: Component loaded (static import)

7. **ThemeData fetch for CSS Variables**
   - `ThemeDataService.listAll(themeName)`
   - Settings namespaced as `--theme-setting-<key>`
   - State: CSS variables ready

8. **Dual-store context synchronization**
   - `getThemeStore()` → sets themeName and currentPost in returned store
   - `getReactStore()` → sets themeName and currentPost in React.cache (safe fallback)
   - State: Context synchronized in both stores

9. **Rendering with isolated CSS**
   - Theme CSS already embedded in `theme-styles.css` via `theme-styles.css` imported in `globals.css`
   - Isolation via `.blacklotuscms-theme[data-bl-theme="id"]` (fallback) + `@scope` (Chrome 118+)
   - State: Page rendered

## Develop New Theme

1. **Create theme folder**
   - `themes/my-theme/` copying from `themes/default/`
   - State: Structure created

2. **Define manifest**
   - `theme.json` with `name`, `version`, `themeApiVersion: 1`
   - State: Valid manifest

3. **Create layouts**
   - `theme.ts` exporting layouts (page, post, archive, search, category, blog, notFound)
   - `layouts/` with React Server components
   - State: Layouts defined

4. **Define styles**
   - `style.css` with pure CSS using `.blacklotuscms-theme` as root
   - Custom CSS variables with own prefix (`--my-*`)
   - Official Tailwind v4 tokens overridden in `.blacklotuscms-theme`
   - State: Styles defined

5. **Run build**
   - `npm run themes:generate` (automatically executed by `predev`/`prebuild`)
   - Script validates manifest, CSS variables, keyframes namespacing
   - Generates `src/generated/theme-registry.ts` and `src/generated/theme-styles.css`
   - State: Theme ready for use

6. **Enable in panel**
   - Admin selects theme in `/admin/themes`
   - `ThemeService.setActiveTheme()`
   - State: Theme active

## Manage Theme Permissions

1. **Theme attempts to access data** (e.g., db.read.post)
   - State: Call received

2. **ThemeDataService.validate(capability)**
   - Checks in-memory cache (Map<string, CacheEntry> with 10s TTL)
   - If cache hit and status = "approved": returns true immediately
   - If cache hit and status != "approved": throws error + requestPermission()
   - If cache miss: queries ThemePermission in database
   - Stores result in cache with TTL (expiresAt = now + 10s)
   - State: Permission verified (via cache or database)

3. **If not approved: requestPermission()**
   - Creates/requests ThemePermission with status "pending"
   - Clears permission cache for affected theme
   - State: Request registered

4. **Admin approves/denies via panel**
   - Clears permission cache for affected theme
   - State: Permission processed

## Modify Existing Theme

1. **Edit files in repository**
   - `style.css`, layouts, `theme.json`
   - State: Changes made

2. **Restart dev server or run build**
   - `npm run dev` or `npm run build`
   - `themes:generate` runs automatically via hooks
   - State: Theme regenerated

3. **Verify result**
   - Test in browser
   - State: Theme updated
